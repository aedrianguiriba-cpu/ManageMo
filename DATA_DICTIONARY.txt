======================================================================
MANAGEMO DATA DICTIONARY
======================================================================

Database: PostgreSQL on Supabase. Source: database/schema.sql.
Row level security is disabled on every table because the PHP session handles access control.

Conventions
- PK = primary key, UQ = unique, FK (soft) = points to another table but no foreign key is enforced in the database.
- college_id on any table holds a departments.abbreviation. The department can be a college, an office or a campus.
- Descriptions marked * are inferred from the column name and surrounding code comments, not stated in the schema.

TABLES AT A GLANCE
------------------

> users
    Purpose: Accounts for admins and regular users

> departments
    Purpose: Colleges, offices and campuses (one list)

> inventory
    Purpose: One row per physical item or stock line

> requests
    Purpose: Borrow, item, service and condemnation requests

> request_items
    Purpose: Line items attached to a request

> borrow_records
    Purpose: History of items lent out and returned

> user_owned_items
    Purpose: Items a user or department already owns

> notifications
    Purpose: Messages shown in the notification bell

> app_settings
    Purpose: Site-wide key/value settings

USERS

RELATIONSHIPS
-------------

> requests.user_id
    To: users.id
    Meaning: Who asked

> requests.approved_by
    To: users.id
    Meaning: Admin who decided

> requests.inventory_id
    To: inventory.id
    Meaning: Unit requested

> request_items.request_id
    To: requests.id
    Meaning: Lines of a request

> request_items.inventory_id
    To: inventory.id
    Meaning: Unit on a line

> borrow_records.user_id
    To: users.id
    Meaning: Borrower

> borrow_records.inventory_id
    To: inventory.id
    Meaning: Item lent

> borrow_records.request_id
    To: requests.id
    Meaning: Request behind the loan

> user_owned_items.user_id
    To: users.id
    Meaning: Owner

> notifications.user_id
    To: users.id
    Meaning: Recipient

> inventory.condemned_by, disposed_by
    To: users.id
    Meaning: Admin who acted

> users / inventory / user_owned_items .college_id
    To: departments.abbreviation
    Meaning: Affiliation. A text match, not an enforced key

None of these are database foreign keys. The application is responsible for keeping them consistent.

NOTES
-----

- There is no campuses table. Campuses are departments rows with type = 'campus'.
- inventory.campus_id, users.campus_id and user_owned_items.campus_id were removed. college_id is the only ownership field.
- Most ID columns that point at other tables are INT while the primary keys are BIGSERIAL. This works for current data sizes but the types do not match.
- Seed data in the schema file includes four demo users and sample inventory, requests and borrow records.
